# 「说开」AI 私人对话与记忆 UX 设计

状态：实现基线
范围：uni-app H5 与 mp-weixin 共用代码；测试环境先行
原则：私人内容默认不共享，长期记忆必须由用户确认，关系记忆必须由双方确认

## 1. 用户目标与主要任务

目标用户是已经进入一间沟通房间、需要先私下把事情说清楚的一方。用户的核心目标不是“训练一个模型”，而是：

1. 重新打开房间时，继续上次没有讲完的 AI 私人对话。
2. 知道 AI 当前记住了什么、为什么记住，并能修改或忘记。
3. 让 AI 在以后相似沟通中少问已经确认过的背景，但不把私人信息泄露给对方。
4. 只把双方都明确确认的内容沉淀为关系记忆。

## 2. 信息架构

### 2.1 AI 私人对话

仍位于房间“AI 对话”阶段，是每次沟通的主任务页面。新增：

- 服务端恢复状态：恢复成功时在对话流内显示“已恢复上次与 AI 的私人对话”。
- 保存状态：输入框下方显示“正在保存 / 已保存 / 保存失败，点击重试 / 离线，仅保存在本机”。
- 记忆候选：只有 AI 已听清并提出长期记忆候选时，才在对话尾部显示“这次有内容值得下次记住”。
- 用户可选择“记住这条”“只用于这次”“修改后记住”。不处理候选不阻断选择表达路径。

### 2.2 我的空间

在现有“当前沟通”和“历史沟通”之间增加两个入口：

- `历史 AI 对话`：按最近更新时间排列，行首显示沟通主题，辅文显示角色、上次聊到的摘要和时间。点击后进入对应房间并恢复私人对话。
- `AI 记住了什么`：显示已确认的个人记忆和等待处理的候选。每条说明“用于什么”“来自哪次沟通”，并提供修改与忘记。

历史列表使用连续的档案行，不把每一项再包成独立卡片；记忆条目是可单独处理的内容单位，可使用轻量卡片。

### 2.3 关系记忆

不单独暴露私人推断。只有某条内容已经进入双方可见区，并由双方分别确认后，才显示在“共同记住的事”中。任一方撤回后立即停止用于后续 AI 检索，并显示“已停止使用”。

## 3. 关键流程与返回行为

### 3.1 恢复私人对话

1. 用户从邀请链接、历史沟通或当前房间进入。
2. 客户端先显示本机缓存，再请求服务端当前用户在该房间的私人对话。
3. 服务端版本更新时，以服务端已确认保存的消息为准；若新版本已经换了问题，本机旧答案移入“未发送草稿”卡片，不能自动挂到新问题下。用户可手动放回输入框或丢弃。
4. 对话恢复后回到原滚动位置附近，显示非阻塞恢复提示。
5. 返回按钮回到首页；已发送消息保存在服务端，未发送输入按房间单独自动保存。

### 3.2 确认个人记忆

1. AI 听清当前背景后，最多提出三条可复用的记忆候选。
2. 候选明确标注类型：需要、触发点、沟通偏好、边界、修复方式。
3. 用户选择“记住这条”后，行内状态变为“以后可用于你的私人对话”。
4. 选择“修改后记住”打开短任务编辑层；保存或取消都能退出。
5. 选择“只用于这次”后候选消失，但原始对话仍保留在该房间历史中。

### 3.3 忘记个人记忆

1. 用户在“AI 记住了什么”点击“忘记”。
2. 确认层说明：这会停止 AI 在以后对话中使用该条记忆，不会删除其来源房间的历史对话；确认按钮为“停止记住”，取消为“继续保留”。
3. 成功后原位更新，不弹出成功对话框；失败时保留原内容并给出重试。

### 3.4 关系记忆确认

1. 关系记忆只能从双方已分享、已确认的共同内容产生。
2. 双方分别看到相同候选及来源，选择“同意共同记住”或“这次不要记住”。
3. 两人均同意后才进入 ACTIVE；此前为等待确认且不参与 AI 检索。
4. 任一方停止共同记住后变为 REVOKED，不再参与检索。

## 4. AI 检索边界与透明度

每次私人追问只向模型提供：

1. 当前房间最近消息和滚动摘要；
2. 当前房间上下文；
3. 当前登录用户明确确认、且与本次语义相关的个人记忆；
4. 与当前对方之间、双方都确认的关系记忆；
5. 未解决议题和曾被双方确认有效的修复方式。

不会提供对方的私人对话、对方个人记忆、被拒绝或已忘记的候选。UI 文案使用“AI 会参考你确认过的内容”，不宣称模型被永久训练。

## 6. 文案基线

- 恢复成功：`已恢复上次与 AI 的私人对话。只有你能看到。`
- 服务端保存中：`正在保存这段私人对话…`
- 保存成功：`私人对话已保存`
- 离线：`当前离线。未发送内容已保存在本机，联网后再发送。`
- 记忆候选标题：`这次有内容值得下次记住`
- 候选说明：`只有你确认后，AI 才会在以后相似的私人对话中参考。`
- 空记忆：`AI 还没有记住长期内容。只有你亲自确认的内容才会出现在这里。`
- 忘记后果：`停止记住后，AI 不会再在以后对话中使用这条内容；来源房间的历史对话仍会保留。`
- 恢复失败：`暂时无法读取上次的私人对话。本机内容仍在，请检查网络后重新读取。`

所有错误写明原因和下一步，不显示 RPC、JWT、内部 ID 或模型参数。

## 7. 视觉与交互

- 延续暖纸色、墨绿正文、珊瑚强调和宋体大标题。
- 历史对话采用“档案索引”节奏：细分隔线、主题优先、摘要和时间降级，不堆叠阴影卡片。
- 记忆采用“页边批注”意象：左侧细色线区分需要、偏好、边界、修复方式；不使用通用 AI 渐变或发光效果。
- 页面保持单一纵向滚动，不嵌套同向滚动区域。
- 主操作始终只有一个高强调按钮；忘记是低强调破坏性操作。

## 8. 无障碍与适配

- 所有按钮至少 44pt/48dp；图标按钮具有可访问名称。
- 动态恢复、保存、成功和错误通过文字与视觉状态共同表达，并使用可被辅助技术感知的状态区域。
- 输入框、标签、错误和发送按钮在键盘打开时仍可见或可达。
- 200% 字号时历史行和记忆卡自动增高，不固定高度、不截断关键主题。
- 窄屏保持单列；宽屏限制内容最大宽度，不把输入框和确认层无限拉伸。
- 背景可延伸到安全区，交互控件必须位于安全区和键盘 inset 之内。
- 减少动态效果开启时，去除上浮位移动画，只保留轻微淡入。

## 10. 数据与删除语义

- 退出登录：按原产品承诺清除本机所有房间入口和私人草稿；服务端历史不因退出而删除，重新登录仍可恢复。
- 开新房间、加入房间、切换历史房间：只切换当前房间，不删除其他房间本机草稿。
- 忘记个人记忆：将记忆标为 FORGOTTEN 并停止检索；来源对话独立保留。
- 删除私人对话：本次不在首屏提供批量删除；服务端接口保留按会话删除能力，后续设置页补充。此项在正式开放用户前必须提供可发现入口。
