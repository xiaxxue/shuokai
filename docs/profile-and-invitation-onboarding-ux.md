# 「说开」个人资料与首次邀请引导 UX 设计

状态：已实现并通过独立设计与代码门禁
范围：uni-app H5 与微信小程序共用代码
Tier：T1（跨注册、发起邀请、受邀确认的多页面新功能）

## 1. 用户目标与成功标准

目标用户包括第一次注册的参与者、第一次发起沟通的人，以及第一次接受邀请的人。用户目标不是建立心理档案，而是：

1. 用最少信息告诉系统怎样称呼自己、希望 AI 使用怎样的表达方式。
2. 发起沟通时快速说明双方关系、相处方式和自己观察到的沟通差异。
3. 在提交前准确预览哪些内容会让对方看到，哪些只供自己的私人 AI 参考。
4. 受邀者能独立确认共同背景、保留不同版本，并填写自己的私人视角。
5. 不填写任何可选资料也能完成原有沟通流程。

成功标准：

- 新账号只需一个称呼即可开始；所有偏好均可跳过。
- 首次关系背景在 60–90 秒完成；返回、旋转、前后台切换、刷新和网络失败不丢输入。
- 发起者不能替受邀者写入人口信息、人格、需要、动机或状态。
- 新增字段进入共同 Agent 的数量为零；共同理解仍只使用双方确认分享的表达卡和既有双方确认材料。
- 受邀者选择不同版本时并列保存，不自动合并为事实。

## 2. 主要任务

### Primary

1. 新用户设置称呼并进入首页。
2. 发起者补充或跳过关系背景，确认分享边界后继续原有目标和私人表达。
3. 受邀者确认、修改或跳过邀请方的关系背景，并确认自己的分享边界。

### Secondary

1. 用户从“我的空间”修改称呼、表达偏好，或清空可选资料。
2. AI 在私人对话中说明本次参考了什么，并允许逐项停用。
3. 同一账号后续复用稳定偏好，不重复展示完整引导。

## 3. 产品范围与明确延期

首版注册只收称呼，并可选收“回答长度偏好”和“常用语言”。年龄、性别、成长地区不进入注册主流程：

- 年龄不能替代“希望回答简洁还是详细”的直接偏好；未成年人支持与合规策略未确定前不收年龄。
- 性别当前没有必要的产品用途；不为了“资料完整”而收集。
- 地域/文化只在用户认为与本次议题有关时，以本人短句临时说明，不建立长期地域档案。

大五人格、依恋类型、人格兼容度、关系健康分和 AI 从聊天推断人格均不在首版。

## 4. 平台、路由与持久化

### 4.1 新增持久化子状态

不改变公共房间主状态值，新增两项带 revision 的服务端子状态，并由路由在每次恢复时读取：

- `profileStatus`: `MISSING | ACTIVE`。
- `roomContextStatus`: 发起者 `MISSING | DRAFT | CONFIRMED | SKIPPED`；受邀者 `PENDING | CONFIRMED | DIFFERENT | SKIPPED`。

新增客户端阶段：

- `RELATIONSHIP_SETUP`：发起者关系背景。
- `RELATIONSHIP_CONFIRMATION`：受邀者确认与独立填写。

路由规则：

```text
A + GOAL_SETTING + context MISSING/DRAFT → RELATIONSHIP_SETUP
A + GOAL_SETTING + context CONFIRMED/SKIPPED → GOAL
B + B_DRAFTING + response PENDING → RELATIONSHIP_CONFIRMATION
B + B_DRAFTING + response CONFIRMED/DIFFERENT/SKIPPED → INVITATION_INTRO 或 RECORD
```

“跳过”也是服务端记录的明确状态，因此换端、刷新或深链不会重复拦截。所有可选项可跳过；关系类型不再是服务器硬性前置，避免资料收集阻断核心沟通。

### 4.2 平台行为

- H5：浏览器返回等同页面返回；每次输入变更均同步、立即写入本机，不用防抖承担持久化；`pagehide` 和 `visibilitychange` 再同步 flush 当前快照。刷新、输入后 250ms 内快速关闭标签页、崩溃后重开均纳入不丢最后一次输入的验收。
- 微信小程序：系统返回回到上一步；从分享卡进入时先完成平台登录，再按服务端子状态落到确认页；进入后台立即持久化本机草稿。
- Android predictive back 与 iOS 返回手势只补充可见返回按钮，不被拦截；若第一页存在未同步输入，显示说明后允许离开。
- 窗口旋转、宽度变化、横竖屏和前后台切换保留当前 step、选择、文本、错误与滚动位置。布局按窗口宽度分支：窄屏单列，宽屏内容最大宽度 720px，不按设备型号判断。

## 5. 字段级数据与 AI 权限矩阵

`AI 开关`表示用户可以在预览页关闭“供我的私人 AI 参考”；关闭后仍可用于本人查看，但不进入模型请求。

| 字段 | Owner / Source | 可见范围与分享同意 | 私人 AI | 共同 Agent | 有效期 / 删除 | Version |
|---|---|---|---|---|---|---|
| 称呼 | 本人 / 本人填写 | 创建或加入后的同房间参与者；保存前明确说明 | 仅用于称呼 | 否 | 账号期；可改名，既有房间保留加入时快照 | profile revision |
| 回答长度偏好 | 本人 / 本人选择 | 仅本人 | 默认开，可逐项关闭 | 否 | 直到清空 | profile revision |
| 常用语言 | 本人 / 本人选择 | 仅本人 | 默认开，可逐项关闭 | 否 | 直到清空 | profile revision |
| A 的关系类型/时长/相处方式 | A / A 填写 | B 可见；明确标记“邀请方版本，待确认” | A 可开关；B 端默认关闭，只有 B 在预览页独立打开`让我的私人 AI 参考邀请方版本`后才可用 | 否 | 本房间；A 可在 B 响应前编辑或跳过 | shared context revision + B consent revision |
| B 的不同版本 | B / B 填写 | 提交预览后共享给 A；可选择不共享并改为 SKIPPED | B 可开关 | 否 | 本房间；可在进入表达前修改 | response revision + seen shared revision |
| 每人的沟通倾向 | 各本人 / 本人选择 | 仅本人 | 默认开，可逐项关闭 | 否 | 本房间；房间结束后不再检索 | participant context revision |
| 当前关系状态 | 各本人 / 本人选择 | 仅本人 | 默认开，可逐项关闭 | 否 | 本房间 | participant context revision |
| 我观察到的差异 | 各本人 / 本人短句 | 仅本人，永远不写入对方资料 | 默认开，可关闭 | 否 | 本房间 | participant context revision |
| 文化背景为何与本次有关 | 各本人 / 本人短句 | 仅本人 | 默认关，用户在预览页主动打开 | 否 | 本房间 | participant context revision |

服务端采用 allowlist：本次新增 RPC 不向共同 Agent 提供任何字段。受邀者未确认的 A 版本、双方不同版本和所有私人视角均不能进入共同理解或行动候选。

## 6. 用户流程

### 6.1 注册后最小资料

```text
完成平台登录
  → 读取 profileStatus
  → MISSING：打开个人资料 sheet
  → 填写称呼；可选设置回答长度与常用语言
  → 预览“对方可见/仅本人/供私人 AI 参考”
  → 保存或“只保存称呼”
  → 首页
```

- 称呼是参与房间的最小必要信息，可使用化名；关闭按钮文案为`关闭并保留草稿`，只写本机、不提交任何字段，之后创建/加入前仍只补问称呼。
- `只保存称呼`会联网提交称呼并跳过可选偏好；提交成功后不自动重开完整引导。两个操作的文案和结果不复用。
- 用户主动创建或加入房间而称呼仍为空时，只显示单字段称呼页，不展示可选偏好。

### 6.2 发起者关系背景

```text
创建房间
  → Step 1 介绍你们：关系类型、时长、相处方式（均可跳过）
  → Step 2 只描述自己：沟通节奏、表达方式、情绪/方案偏好、计划方式
  → Step 3 本次私人视角：当前关系状态、主要差异、文化背景是否相关
  → Step 4 精确预览：给对方看的字段 / 仅本人字段 / AI 开关
  → CONFIRMED 或 SKIPPED
  → 原有 GOAL
```

每一步改变立即写入本机房间草稿；点击下一步时写入服务端 DRAFT。离线时允许继续编辑，但最终确认显示`需要联网才能保存并继续`，输入不清空。

### 6.3 受邀者确认与独立填写

```text
加入房间
  → 查看 A 版本
  → 选择“符合我的理解 / 填写我的版本 / 暂不回答”
  → 可选填写自己的私人沟通倾向与当前关系视角
  → 受邀者精确预览：将分享给 A 的字段 / 仅本人字段 / AI 开关
  → 保存 CONFIRMED / DIFFERENT / SKIPPED
  → 原有 INVITATION_INTRO
```

三个决定的后果：

- `符合我的理解`：A 会看到“已确认”；不会让共同 Agent 使用这些字段。
- `填写我的版本`：A 会看到 B 明确预览并提交的版本；两种版本并列，不判断对错。
- `暂不回答`：A 只看到“对方暂未确认关系背景”，不会看到私人沟通倾向。

### 6.4 返回、恢复与并发

- 步骤内返回：保留全部输入和错误；第一页返回首页时说明“草稿仍保存在这台设备”。
- 换端：恢复已同步 DRAFT 的 step 和字段；未同步本机内容留在原设备。
- 并发更新：提交携带 expected revision。冲突时保留本机输入，显示`这份背景刚刚在另一处更新。重新读取后，再确认要保留哪一版。`，提供`重新读取`和`保留本机内容`。
- B 响应绑定 `seenSharedRevision`。A 修改共享字段会使 B 响应变回 PENDING；但 A 私人字段变化不影响 B。
- 新字段当前不参与邀请摘要、共同理解或行动候选，因此修改它们不失效这些下游结果。若未来让任何生成任务读取这些字段，必须把 context revision 加入输入绑定，并使旧结果 STALE 后重算。

## 7. 页面、控件、校验与文案

### 7.1 个人资料 sheet

- 标题：`先告诉我怎么称呼你`
- 说明：`称呼会在你加入沟通后展示。偏好默认只属于你。`
- `称呼（必填）`：1–30 个可见字符，NFKC 归一化，去首尾和重复空白；允许中文、字母、数字和常见符号，不要求真实姓名。
- `回答长度（选填）`：简短 / 适中 / 详细。
- `常用语言（选填）`：简体中文 / 繁体中文 / English / 其他；“其他”出现 1–30 字输入。
- 主按钮：`保存并进入说开`；仅称呼存在时可用，旁边始终显示启用条件。
- 次按钮：`只保存称呼`。
- AI 说明：`私人 AI 在云端处理。你可以关闭每项偏好的 AI 使用。`

错误：

- 称呼为空：`请填写一个希望别人怎样称呼你的名字，也可以使用化名。`
- 称呼过长：`称呼最多 30 个字符，请缩短后再保存。`
- 其他语言为空：`请填写常用语言，或选择上面的已有选项。`
- 冲突：见 6.4。

### 7.2 发起者 Step 1–4

- Step 1：`先介绍一下你们`；所有字段选填，页面首部提供`暂不补充关系背景`。
- Step 2：`发生分歧时，你通常怎样沟通？`；只描述本人，三个明确文本选项，不使用滑杆。
- Step 3：`你眼中的关系现在怎样？`；开放文本最多 300 字，文化说明最多 300 字；字段在失焦或提交时校验。
- Step 4：`确认这次会怎样使用`；两个连续列表区，不把每项包成卡片：
  - `会让对方确认`：逐字展示关系类型/时长/相处方式。
  - `只属于我`：逐字展示私人视角，每项有`供私人 AI 参考`开关和`为什么会参考`说明。
- 主按钮：`保存背景并继续`；次操作：`全部跳过并继续`。

Step 1 选项契约（所有组都有`暂不填写`，不选择也可继续）：

- 关系类型：`恋人/伴侣`、`夫妻`、`家人`、`朋友`、`同事/合作伙伴`、`其他`；选择`其他`后显示 1–30 个可见字符的自定义输入，清除输入会回到未完成状态。
- 相处时长：`不到 3 个月`、`3–12 个月`、`1–3 年`、`3–7 年`、`7 年以上`、`不适用/不确定`；只保存区间，不收开始日期。
- 当前相处方式：`主要线下见面`、`主要异地/线上`、`两者都有`、`最近发生了变化`、`不适用/不确定`；“主要”描述当下常态，不暗示关系质量。
- B 选择`填写我的版本`时使用完全相同的选项、`其他`条件和校验；两版并列保存。

### 7.3 受邀确认与预览

- 标题：`对方这样介绍你们的关系`
- 说明：`这是邀请方的版本，不是系统认定的事实。`
- 决定按钮：`符合我的理解` / `填写我的版本` / `暂不回答`。
- B 的“我的版本”使用与 A 相同的选择控件和长度限制。
- 最终页标题：`确认你会分享什么`
- 共享区：只列 B 主动填写的不同版本；私人区列 B 沟通倾向和状态。
- A 已分享的版本另列为`邀请方提供、我可以看到`；旁边有独立开关`让我的私人 AI 参考邀请方版本`，默认关闭。预览明确说明：不开启时内容只供 B 阅读，不会发送给模型；开启只影响 B 的私人 AI，不影响 A 或共同 Agent。
- 主按钮：`保存我的选择`。

### 7.4 AI 透明度

- AI 生成或整理的内容统一显示`AI 整理`徽标；本人输入显示`你填写`。
- 私人对话顶部增加可展开的`本次 AI 参考了什么`，列出启用的资料、来源、最后更新时间和`本次不用`。
- 每项提供`为什么参考`：例如`你选择了“先理解感受”，所以 AI 会先帮助你说清感受，再讨论方案。`
- 云端说明：`由 Cloudflare Workers AI 在云端处理本次允许参考的内容。说开把你启用的资料与本次对话保存在自己的 Supabase 私有数据库：个人偏好保留到你清空，房间资料保留到房间删除或到期。当前没有为模型输入输出启用 Cloudflare R2、KV、Durable Objects、Vectorize 或 AI Gateway 持久日志，因此 Cloudflare 不另存模型内容；Cloudflare 声明未经明确同意不会用 Customer Content 训练模型或改进 Cloudflare/第三方服务。删除说开的字段会删除 Supabase 中对应副本，但不能撤回已经完成的一次计算。`
- 上述说明下方提供可聚焦链接`查看 AI 与资料隐私说明`，展示服务商、当前模型、说开保存期限、Cloudflare 不训练/不改进声明、已启用的基础设施存储清单和删除范围。上线门禁会读取实际配置；只要启用了 AI Gateway 持久日志或任何 Cloudflare 内容存储而说明未同步更新，就禁止真实资料进入模型。
- 模型供应商或主要模型变化时，在首次使用 AI 前显示非阻塞变更说明。

## 9. 删除、清空和版本失效

- `清空可选资料`只清除回答长度、常用语言和对应 AI 开关，不删除账号、称呼、历史房间或历史对话。
- 清空是服务端硬删除字段值，不提供 Undo；确认层必须逐项说明损失，按钮为`清空这些偏好`，取消为`继续保留`。用户以后可重新填写，但原值不可恢复。
- `本次不用`只关闭当前模型请求，不删除资料；入口与清空物理分离。
- 昵称修改不改写既有 participant 快照，只影响未来创建/加入的房间；现有房间保持当时称呼，避免历史归属漂移。
- A 修改共享字段时 shared revision 增加，B 旧响应失效。A 私人字段修改只增加 participant revision，不影响 B。
- 每次私人 AI 请求携带并在服务端绑定 `profileRevision + participantRevision + consentRevision + seenSharedRevision`。模型返回前重新读取这组 revision；任一项变化时，不保存也不展示旧结果，返回 `CONTEXT_STALE` 并让用户用当前开关重试。关闭 AI 开关、清空字段或 B 撤回对 A 版本的同意都会先增加 consent revision，因此并发中的旧请求必定失效。
- 本版本的邀请摘要、共同理解和行动候选不读取新增上下文，因此不因上下文修改失效；一旦未来接入，必须绑定对应 revision 并让旧结果变为 STALE。

## 10. 数据与安全实现边界

- 资料与房间上下文存 private schema；authenticated/anon 不具备表级读取权限，只通过 security-definer RPC。
- RPC 根据 `auth.uid()` 和 room participant 角色裁剪返回，拒绝无关账号和跨房间读取。
- 前端只使用 publishable/anon key；service secret 仍只存在 Worker。
- 短文本执行长度、Unicode 归一化和空白归一化；渲染保持文本节点，不使用 HTML 注入。
- 日志、队列和错误不记录称呼、关系背景、私人选择或地域文化短句，只记录稳定错误码和请求 ID。
- 私人 AI 请求只包含当前用户启用的 profile/participant context，不包含另一方私人 context。
- 本机资料草稿 key 至少包含 `authUserId`；房间草稿 key 包含 `authUserId:roomId:role`，恢复前必须同时匹配当前认证用户、房间和角色。登出、检测到账户切换或身份恢复失败时清除该用户的 profile 草稿及所有房间上下文草稿；绝不把旧账号草稿展示给新账号。测试覆盖同设备 A→登出→B、身份恢复失败、同账号跨房间和同房间角色变化。

## 11. 可访问性、视觉和适配

- 所有操作最少 48dp/44pt；选项使用带文本的 button/radio，不使用只能拖动的 slider。
- 每个输入有常驻 label、必填/选填、支持文本和文字错误；“其他”分支出现时立即进入读取顺序。
- 选择状态同时使用文字`已选择`、标记和颜色；进度显示`第 2 步，共 4 步`，不只显示进度条。
- 读取顺序：返回/关闭 → 标题与说明 → 进度 → 字段 → 就近错误 → 次操作 → 主操作。
- 200% 字号下自动换行、不固定行高；单一纵向滚动；焦点输入位于键盘上方。
- 安全区：底部操作 padding 使用 `safe-area-inset-bottom`；Android edge-to-edge 与 predictive back 实装后实测。
- Profile sheet 打开后焦点进入标题；Tab/Shift+Tab 被约束在 sheet 内，Escape/关闭按钮均执行同一关闭语义。关闭后焦点回到打开它的`编辑个人资料`或首次登录触发器；保存校验失败时焦点移动到首个无效字段，服务端错误时焦点移动到错误摘要，重试后回到触发操作。
- 新页面使用已测颜色：`#1c2923`/`#fffdf8` 14.85:1，`#68726c`/`#fffdf8` 4.90:1，`#be442e`/`#fffdf8` 5.18:1；白字主按钮使用 `#be442e`（5.18:1），不使用白字配 `#df5b3f`（3.68:1）。非文字选中边框实测至少 3:1。
