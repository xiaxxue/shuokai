# 说开 SHUOKAI

一个带持久化后端的结构化沟通产品原型：当普通聊天陷入重复、误解或升级，帮助双方先分别表达，再共同看见事实、理解、影响、请求与真实分歧。

## 原型覆盖的流程

- 选择本次沟通目标
- 语音表达与本地录音预览
- AI 单问题澄清（模拟内容）
- 本人审核并批准观点卡
- 低压力邀请对方加入
- 双方共同视图与分歧定位
- 创建可逆、可复盘的 7 天实验
- 工程视图展示状态机事件

## 后端能力

- D1 持久化房间、参与者、私人草稿、批准后的观点卡、共同视图与约定
- 服务端状态机校验合法状态迁移，模型不能直接控制流程
- 参与者使用不可猜测令牌进入房间，数据库只保存令牌哈希
- 原始转写仅返回给内容所有者；共同视图只读取双方批准后的观点卡
- 真实房间码与邀请链接；第二个浏览器可以作为 B 独立加入
- 事件日志记录状态迁移，但不写入原始私人表达

核心 API 位于 `POST /api/rooms`，通过显式 action 完成创建房间、加入、保存私人草稿、批准观点卡、生成共同视图和双方确认约定。`GET /api/rooms` 只返回当前参与者有权查看的数据。

## 本地运行

```bash
npm install
npm run dev
```

验证：

```bash
npm run lint
npm test
```

当前录音仍保留在浏览器本机，不上传服务器。房间、双方批准记录和状态事件会持久化。AI 转写与观点卡生成仍使用演示内容，正式接入模型时会继续沿用同一套“生成—本人修改—本人批准”的权限边界。
