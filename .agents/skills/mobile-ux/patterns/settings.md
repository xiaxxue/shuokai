# Pattern: Settings

設定画面。

## いつ使うか

ユーザーごとに答えが分かれ、かつ推測では決められない選択肢がある場合。
**設定項目の追加は設計の失敗を先送りする手段になりうる。** 「どちらが良いか決められないから設定にする」は、全ユーザーに判断を押し付けている。まず良い既定値を選ぶ。

## 設計手順

1. **各項目に「既定値で足りないか」を問う** — 足りるなら設定にしない。
2. **設定ではなく文脈に置けないか検討する** — その機能を使っている場所で切り替えられるなら、そこに置くほうが発見される（例: 並び順は一覧画面のツールバー、設定画面ではなく）。
3. **グルーピングする** — 項目が7つを超えるならセクションに分ける。セクション見出しはユーザーの語彙で書く（WRITE-004）。
4. **現在値を一覧上で見せる** — 行をタップしないと現在値が分からない設定は、確認のために毎回開くことになる。
5. **即時反映を既定にする** — 設定画面に「保存」ボタンを置かない。トグルや選択は即座に反映し、必要なら結果を見せる（STATE-007）。
6. **破壊的項目を分離する** — データ削除・アカウント削除・リセットは末尾に置き、他の項目と視覚的に分ける（DESTR-003）。
7. **状態を設計する** — 通信を伴う設定（同期・通知）は loading / error / offline が発生する。トグルが戻ってしまうケースの表示を決める。

## 関連ルール

FOUND-005（見せる情報の絞り込み）、FOUND-006（用語の一貫性）、WRITE-004（ユーザーの語彙）、STATE-007（変更完了のフィードバック）、STATE-008（無効状態の説明）、DESTR-003（破壊的項目の分離）、LIST-001（設定行をカードにしない）。

## よくある失敗

- 決められなかった設計判断を設定項目として積み上げる
- 現在値が行に表示されず、確認のために全項目を開く必要がある
- 設定画面に「保存」ボタンがあり、押し忘れで変更が失われる
- 通信を伴うトグルが失敗しても無言で元に戻る
- アカウント削除が他の項目と同じ見た目で並んでいる
