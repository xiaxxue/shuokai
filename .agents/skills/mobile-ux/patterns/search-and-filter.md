# Pattern: Search and Filter

検索と絞り込み。

## いつ使うか

対象件数が増えると目視で探せなくなるコレクションがある場合。件数が常に十数件程度なら、検索より並び順とグルーピングで解決するほうが良い。

## 設計手順

1. **検索が主機能か副機能かを決める** — 主機能なら独立した入口（検索タブ、または常時表示の検索欄）を与える。副機能ならツールバーの検索アイコンで足りる。この判断で配置が決まる。
2. **検索対象を明示する** — 何が検索されるのか（タイトルのみか、著者やメモも含むか）が分からないと、ヒットしない理由がユーザーに分からない。プレースホルダーではなくサポートテキストか結果画面で示す。
3. **入力量を減らす** — 履歴、候補（サジェスト）、直近の項目を提示する。モバイルのキーボード入力は最大のコストであり、候補提示は最も費用対効果が高い施策。
4. **結果の状態を全部設計する** — 入力前（履歴・候補）、入力中（インクリメンタル or 確定検索）、結果あり、結果ゼロ、エラー、オフライン。**結果ゼロは必ず設計する**（STATE-004, WRITE-006）。
5. **絞り込みの現在値を常に見せる** — 適用中のフィルタが見えないと、ゼロ件の原因がフィルタなのかデータなのか判別できない。解除の導線も同じ場所に置く。
6. **検索とフィルタの関係を決める** — フィルタは検索結果に対して適用されるのか、全体に適用されるのか。曖昧なままにしない。
7. **履歴の削除手段を用意する** — 検索履歴は個人情報。消せる導線が要る。

## ゼロ件時の文言

原因ごとに文言を変える（STATE-004 / WRITE-006）。

| 状況 | 文言の型 |
|------|---------|
| クエリに一致なし | 「「〇〇」に一致する本はありません。条件を変えて検索してください。」 |
| フィルタで消えた | 「絞り込み条件に一致する本はありません。 [絞り込みを解除]」 |
| そもそもデータが空 | 「まだ本を登録していません。 [本を追加]」 |

3つを同一の「該当なし」で済ませない。ユーザーが取るべき行動が違う。

## 関連ルール

STATE-004（空・ゼロ件状態）、WRITE-006（空状態の文言）、FORM-001（ラベル）、FORM-004（キーボードタイプ）、NAV-003 / NAV-002（検索を独立した宛先にする場合のタブ構成）、A11Y-007（結果件数の読み上げ通知）。

## よくある失敗

- ゼロ件が真っ白、または「該当なし」だけで次の行動がない
- 適用中のフィルタが見えず、ゼロ件の原因が分からない
- 検索対象が不明で、ヒットしない理由をユーザーが推測できない
- 検索履歴を消せない
- 全文検索が必要ないのにインクリメンタル検索を実装し、1文字ごとにエラーを出す
