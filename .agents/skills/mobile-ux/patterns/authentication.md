# Pattern: Authentication

サインイン・サインアップ。

## いつ使うか

複数端末での同期、他ユーザーとの共有、サーバー側の個人データが必要な場合。
**認証を先に必要としない設計を最初に検討する。** ローカル保存で成立するアプリに認証を付けると、価値を体験する前の離脱要因になる（ONBD-002）。

## 設計手順

1. **認証が必要な範囲を切り分ける** — アプリ全体か、特定機能だけか。「同期したくなったらサインイン」が可能なら、起動時の認証壁をなくせる。
2. **手段を決める** — パスワード、OTP（メール／SMS）、プラットフォームのサインイン、パスキー。手段が多いほど良いわけではない。ユーザーが「前回どれで入ったか」を思い出せない問題が起きるため、既定の1つを明確にする。
3. **サインインとサインアップを混同させない** — 入口を明確に分け、誤って逆に進んだ場合の切り替え導線を各画面に置く。
4. **入力を最小にする** — メールとパスワードのみ。プロフィール情報は後から。autofill / パスワードマネージャに対応させる（FORM-008）。
5. **エラー文言を設計する** — セキュリティ上、どちらが誤りかを明かせない場合がある（WRITE-002 の例外）。その場合も「メールアドレスまたはパスワードが正しくありません。」のように、次の行動が分かる形にする。総当たり防止のロック時は、解除条件と待ち時間を明示する。
6. **OTP・セッションのタイムアウトを設計する** — 期限切れ前に警告し、延長または再送を可能にする（A11Y-008 / WCAG 2.2.1）。コード入力欄は自動入力に対応させ、桁を複数フィールドに分割しない。
7. **サインアウトを破壊的操作として扱う** — ローカルの未同期データが消えるなら、それを明示する（DESTR-002）。
8. **状態を設計する** — 通信中（BTN-005）、認証失敗、アカウントロック、オフライン、セッション期限切れ。

## 関連ルール

ONBD-002（価値の提示を先に）、FORM-001（ラベル）、FORM-006（入力保全）、FORM-008（autofill）、WRITE-002（エラー文言）、BTN-005（送信中の状態）、STATE-005（エラーからの回復）、A11Y-008（タイムアウト）、DESTR-002（サインアウト時のデータ損失）。

## よくある失敗

- ローカルで完結するアプリに起動時サインイン壁を置く
- パスワード欄をエラー時にクリアして再入力させる（FORM-006違反）
- OTPを4つの入力欄に分割し、autofillもペーストも効かない
- 「認証エラー」だけを表示し、再試行の可否も待ち時間も示さない
- サインアウトで未同期データが消えることを告げない
